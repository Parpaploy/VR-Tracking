# VR Tracker — confirmed direction

**Mode:** Operate · web · whole-site redesign
**User-selected world:** Campus equipment circulation ledger
**Build path:** Comp-led, using the user's selected first composition `.impeccable/mocks/dashboard-a.png` as a hierarchy reference.

## Product mechanism

Students scan the VR's QR, attach a selfie with the device, and send a borrow request. An administrator approves or rejects it. Return is completed by an administrator scanning the device QR. The ledger must make these hand-offs and the current owner/status easy to read.

## Direction contract

- **World:** a well-kept equipment issue/return register: warm ivory stock, dark ink, restrained indigo navigation and actions, ruled rows, clear printed column heads, compact status marks, ordered identifiers and times. This is a functional ledger grammar, not a paper texture decoration.
- **First viewport:** the admin opens directly to a live register: pending requests are the first actionable section; counts summarize ready, awaiting approval, borrowed and damaged stock; device rows expose number, QR ID and state. Active requests show the borrower, device and timestamp beside review actions.
- **Visitor path:** admin moves from pending review to inventory and return scan; student moves from sign-in to QR scan, selfie attachment, pending status and personal loan history. Use the same page, field, row, status and action vocabulary throughout.
- **Signature interaction:** opening one ledger row reveals its editable device number, status and delete action; approval is directly beside its request; return scan shows the borrower and loan time before confirmation.
- **System grammar:** warm paper/ink neutrals with indigo `#2e2f70` as the primary interface color. Keep semantic state colors for ready, pending, borrowed and damaged. Stable columns and tabular timestamps. Square-corner controls and surfaces throughout. Rules separate rows; avoid nested cards and heavy shadows. On narrow screens rows become stacked entries without losing field labels.
- **Identity:** use “VR Tracker” only; no university name, logo or seal.
- **Accessibility / behavior:** every status remains written as text alongside its mark; keep keyboard focus visible, use reduced motion, preserve labels and confirmation for destructive or consequential actions, and retain loading, error and empty states.
- **Honest risk:** the ledger metaphor can become decorative or dense. Use it only to clarify columns, chronological hand-offs and state; do not invent due dates, policy, people, or activity.

## Challenger verdicts

- Cassette J-card — competitive on ordered, timed event history; its side A/B split does not explain this product's student/admin workflow. Retain aligned timestamps in history, not the cassette form.
- Airport wayfinding — competitive on clear next actions and strong state emphasis; useful for request review, but a travel sign system does not explain device custody. Keep the next required action prominent.
- Barcode signal field — competitive on connecting with the actual QR mechanism; dense animated bands undermine legibility. Keep crisp scan framing and a static reduced-motion fallback.
- Character goods catalog — declined on audience identification and product clarity; keep its useful rule that inventory entries reflow as whole, stable units.
- Acetate reference manual — declined on audience identification and product clarity; keep its clean separation between a pending item and its review controls.

## Grounded candidates considered

1. Campus library equipment checkout ledger.
2. Workshop parts issue card.
3. University lab bench instrument log.
4. Student equipment cage clipboard.
5. Dance notation score.
6. Campus room wayfinding directory.
7. Rail departure board.

The user chose the campus equipment ledger concept. No challenger replaces it.
